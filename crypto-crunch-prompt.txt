FRONTIER CODING PROMPT — “CRYPTO CRUNCH” MOBILE MATCH-3 GAME

Your objective is to generate a single, fully functional, self-contained HTML file containing HTML, CSS, and modern ES6 JavaScript that implements a polished mobile-first match-3 puzzle game titled:

CRYPTO CRUNCH

The gameplay should be inspired by classic match-3 games such as Candy Crush, Bejeweled, and similar tile-swapping puzzle games, but the visual identity must be original and cryptocurrency themed.

Instead of candy/gems, every board piece is a cryptocurrency logo.

The game must be designed primarily for mobile phones and touchscreen play, while remaining usable with a mouse on desktop.

External standard JavaScript libraries and remote image assets are allowed where useful, but the finished product must remain a single HTML file.

Do NOT output pseudocode, incomplete functions, TODO comments, placeholder interfaces, or explanations.

Return only the complete HTML document.

⸻

1. CORE GAME

Build a complete match-3 game using an approximately:

* 8 × 8 board
* responsive square grid
* portrait mobile-first interface

A player swaps two orthogonally adjacent crypto tiles.

A swap is valid only when it produces a matching line of at least:

* 3 identical logos horizontally, or
* 3 identical logos vertically

When a match occurs:

1. matched pieces animate and disappear
2. pieces above fall downward
3. empty positions are filled with new crypto pieces
4. resulting automatic matches are detected
5. chain reactions continue until the board stabilizes

Invalid swaps should briefly animate and then reverse automatically.

The board must never become logically corrupted during cascades or rapid touchscreen input.

Lock user input while major board-resolution animations are occurring.

5. MATCH DETECTION

Implement robust board logic.

Detect:

* horizontal matches
* vertical matches
* simultaneous intersecting matches
* cascades
* overlapping matches

A matched tile should only be counted once per resolution step even if it participates in multiple lines.

Avoid naïve algorithms that mutate the board while scanning.

Recommended logical sequence:

1. inspect complete board
2. identify all matched coordinates
3. classify special-piece creation
4. remove matches
5. apply gravity
6. generate replacements
7. detect cascades
8. repeat until stable
